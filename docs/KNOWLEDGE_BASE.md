# База знаний проекта

Единая точка входа: что за задача, как оценивается, что реально известно
про данные, как устроен код и что решено/открыто. Детали по областям —
в [`../tasks/backend.md`](../tasks/backend.md) и
[`../tasks/frontend.md`](../tasks/frontend.md); первоисточники — здесь же,
в `docs/`.

## 1. Задача одной фразой

Веб-сервис мониторинга вегетационной динамики сельхозполей: пользователь
выбирает регион/полигон на карте → сервис сам собирает спутниковые
(Sentinel-2/Landsat/MODIS) и метео (ERA5) данные → строит и восстанавливает
временной ряд `primary_ndvi` → детектирует и объясняет аномалии по
Z-score. Плюс отдельный technical batch-инференс для авто-проверки
(`private_features.csv` → `submission.csv`).

Первоисточник: [`tz.pdf`](tz.pdf) («Постановка задачи»).

### Что это меняет по факту (не только «хорошо бы»)

- **Полигонами нужно уметь управлять**, не только добавлять: удаление
  полигона из набора — отдельный подкритерий, сейчас во Flutter такого
  действия нет ни в UI, ни в контракте (`DELETE /polygons/{id}` не описан
  в `tasks/backend.md` — добавить).
- **«Автоматически находить доступные сельхозконтуры при выборе нового
  региона»** — это не то же самое, что «нарисовать свой полигон». Нужен
  сценарий: пользователь указывает регион (например, тянет карту/вводит
  название) → сервис сам предлагает список контуров в этом регионе
  (OSM/ESA WorldCereal), без обязательного ручного рисования. Сейчас
  реализовано только рисование + фиксированный список моковых полигонов.
- **«Отсутствие критической привязки к одному региону»** — прямое
  подтверждение решения уйти от 3 жёстко закодированных демо-регионов
  к полигон-ориентированной архитектуре (уже сделано в rework, см.
  `tasks/frontend.md`), но моковые данные всё ещё эмулируют только 3
  области — стоит проверить на произвольном регионе перед сдачей.
- **Комментарии в коде — на русском.** Весь код на данный момент
  прокомментирован на английском (стандартная практика для Dart/Flutter,
  но противоречит явному критерию). Требует прохода по `frontend/lib/` и
  перевода doc-комментариев на русский.
- **Корневой `README.md` должен позволять запустить решение без правок**
  для максимального балла — не только «инструкция есть», а «инструкция
  реально работает как есть». Проверить весь путь frontend+backend+infra
  перед сдачей.
- Раздел 3 (baseline/эксперименты) — это исследовательский отчёт
  бэкенда/ML, не готовый артефакт репозитория; фиксируется отдельно, когда
  появится ML-пайплайн.

## 3. Реальные данные — сжато

Полная версия — [`../tasks/backend.md`](../tasks/backend.md#1-данные-соревнования).
Файл: [`../data/train_dataset.csv`](../data/train_dataset.csv).

- 99 955 строк, **39 полигонов** (`AOI-0002`…`AOI-0077`), даты
  **2010-04-01…2024-10-30**, шаг — календарный день внутри вегетационного
  сезона (не «раз в пролёт спутника»).
- `primary_ndvi` пуст в **69.5%** строк — это и есть пропуски на
  восстановление; в train нет `is_synthetic_gap` (видимо, только в ещё не
  найденном `private_features.csv`).
- `primary_ndvi` = значение реально снявшего сцену сенсора в приоритете
  S2 > Landsat > MODIS.
- `status`/`ndvi_zscore` в train уже посчитаны организаторами и **точно
  совпадают** с порогами Z во Flutter (`Z≥−1` штатно, `−2≤Z<−1` угнетение,
  `Z<−2` критическая аномалия).
- Культуры реальные, на русском: озимая пшеница, зерновые, подсолнечник,
  пастбища/зерновые — южная степная зона России, **не** совпадает с
  демо-сценарием во Flutter-моке (Меконг/Калифорния/Рондония).
- Координат полигонов в датасете нет — открытый вопрос (см. ниже).

## 6. Журнал решений

- Демо-регионы во Flutter-моке (Меконг/Калифорния/Рондония) оставлены как
  временная заглушка ради быстрого MVP; учитывая, что реальные данные —
  про южную Россию, и критерий требует отсутствия привязки к
  фиксированному набору территорий — пересмотреть сценарий демо, когда
  появятся реальные координаты (п.5.1).
- Пороги Z-score (`ndviStatusForZ`) взяты дословно из `tz.pdf` и совпадают
  с уже посчитанными `status`/`ndvi_zscore` в реальном датасете —
  менять не нужно, только синхронно с бэкендом.
- Убран спекулятивный `/tiles`-эндпоинт (растровые NDVI-тайлы) — в ТЗ
  такого требования нет, карта показывает статус цветом полигона.
