# V22: что отправлять и что изменилось

## Коротко

В систему проверки отправлять файл:

`submission_ensemble_v22.csv`

Это экспериментальный кандидат после официального V19 (`0.0772`). `V20` оставлен как более консервативный запасной вариант. Файлы с `aggressive`, `formula`, `leaf2` и `v21` в названии — внутренние компоненты ансамбля, отдельно их отправлять не нужно.

## Что проверено в данных

- Train: 99 955 строк, 39 полигонов, 30 520 известных значений target.
- Released validation: 57 185 строк, 78 полигонов, 3 112 скрытых точек.
- Финальный test: 49 190 строк, 20 полигонов, 2 323 скрытые точки.
- Распределение расстояния до ближайшего известного наблюдения у pseudo-validation и final test почти совпадает: медиана 2 дня, 90-й перцентиль 7 дней. Поэтому проблема не в том, что synthetic gaps в целом слишком длинные или слишком короткие.
- В исходных сенсорных рядах есть редкие физически невозможные выбросы: 6 в train, 7 в released validation и 8 в final test при грубом диапазоне `[-0.15, 0.98]`.
- Удаление таких выбросов заметно улучшает отдельные искусственные примеры, но не изменило ближайшие опорные значения ни для одного реального final gap. Поэтому насильно переписывать финальный датасет ради V22 не стали: это добавило бы риск без подтверждённой пользы.

## Проверка `known_mask`

Предположение о том, что естественные `NaN` попадают в harmonic/NN-интерполяцию, для текущей ветки не подтвердилось:

- переменной `known_mask` в production-коде нет;
- временные соседи уже выбирались как `target.notna() & ~query_mask`;
- эксперимент с кривыми отдельно использовал `target.notna()`;
- production-модель не содержит отдельную harmonic-регрессию или NN-интерполятор: в ней есть Fourier-признаки и значения временных соседей.

Но `notna()` считает `+inf` и `-inf` известными значениями. Поэтому защита усилена:

- synthetic-mask строится только по конечным target;
- временными опорами могут быть только конечные числовые target;
- то же правило добавлено в curve-эксперимент;
- добавлен тест на естественные `NaN`, `+inf` и `-inf`.

## Как устроен V22

V22 предсказывает не NDVI с нуля, а поправку к сильному V18-бейзлайну.

1. Формульные признаки:
   - расстояния до левого и правого наблюдения, наклоны и экспоненциальные интерполяции;
   - Fourier-признаки дня года;
   - разности, отношения и согласованность Sentinel-2, Landsat и MODIS;
   - погодные и reliability-признаки;
   - расхождение базовых моделей.
2. Collaborative panel-признаки:
   - по значениям других полигонов в те же даты оценивается общий временной сдвиг/шок;
   - query-точки при построении признаков остаются скрытыми.
3. Два residual-эксперта ExtraTrees:
   - target-ID expert обучается на pseudo gaps тех же 20 полигонов, которые есть в final test;
   - ID-agnostic expert обучается на released validation и отвечает за переносимость на реальные гэпы.
4. Симметричный leaf-2 expert стабилизирует первый эксперт.
5. Итог — среднее двух экспертов. Для гэпов с полным размахом между опорами `20 < span <= 40` дней используется leaderboard-подтверждённый V20, потому что новая поправка в этом режиме переносилась хуже.
6. Предсказания ограничиваются физическим диапазоном `[-1, 1]`.

## Как воспроизвести поверх текущего проекта

Архив является addon: распаковать его с заменой файлов поверх текущей папки проекта. Модели и кэши в архив не включены, потому что они весят сотни мегабайт и воспроизводятся скриптами.

```bash
python experiments/search_formula_meta.py
python experiments/build_weather_window_cache.py
python experiments/search_collaborative_shock.py
python experiments/search_asymmetric_id_meta.py
python experiments/train_asymmetric_id_meta.py
python experiments/train_formula_collaborative_leaf2.py
python scripts/predict_ensemble_v20.py
python scripts/predict_ensemble_v22.py
python -m unittest discover -s tests -v
```

Некоторые поисковые скрипты используют кэши и артефакты предыдущих версий проекта (`V18/V19`, multidomain meta). Поэтому их нужно запускать в полной рабочей папке, а не внутри пустой директории только с addon.

## Что сознательно не вошло в V22

- Простое удаление/замена всех выбросов в датасете: не было влияния на реальные final gaps.
- Weather rolling windows по строкам таблицы: строки нерегулярны по времени, поэтому сумма по последним N строкам не является честной суммой за N дней и в абляции ухудшала средний RMSE.
- Отдельная полигональная harmonic-регрессия: пока нет честного out-of-fold подтверждения и она может переобучиться на короткой истории.
- Random split: все основные сравнения сделаны с групповым разделением, чтобы одна и та же группа не утекала из train в validation.
