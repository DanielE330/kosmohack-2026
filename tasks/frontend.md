# Frontend — что осталось

Текущее состояние: карта с полигонами, рисование своего полигона, график
observed/restored NDVI, список аномалий по Z-score — всё работает на
`MockVegetationDataService`. Подробности контракта — в
[`backend.md`](backend.md). Критерии оценки —
[`../docs/KNOWLEDGE_BASE.md`](../docs/KNOWLEDGE_BASE.md#2-критерии-оценки--100-баллов).

## Из критериев оценки — конкретные пробелы (не хватает баллов прямо сейчас)

- **Нет удаления полигона.** Критерий «Управление полигонами» (5 баллов)
  явно требует «добавлять и удалять выбранные участки». Сейчас в
  `MapScreen`/`VegetationDataService` есть только добавление
  (`submitCustomPolygon`); удаления нет ни в UI, ни в контракте (см.
  `DELETE /polygons/{id}` — уже добавлено в `backend.md`, реализовать на
  фронте: кнопка на пине/в деталях полигона + `service.deletePolygon(id)`).
- **Нет «автопоиска контуров при выборе нового региона».** Тот же
  критерий отдельно оценивает это как самостоятельную возможность — не то
  же самое, что «нарисовать свой полигон» руками. Нужен UI-сценарий:
  пользователь указывает регион (поиск по названию или просто
  панорамирует/зумит карту) → запрос списка контуров для этой области
  (`GET /polygons?region=...`, см. `backend.md`) → показываются найденные
  полигоны без ручного рисования.
- **Комментарии в коде — на русском языке** (критерий «Качество кода и
  комментарии», до 3 баллов). Весь текущий код прокомментирован на
  английском — нужно пройтись по `../frontend/lib/` и перевести doc-комментарии.
- **Проверить адаптивность на «чужом» регионе** (критерий «Адаптивность
  под множественные регионы», 5 баллов, требует явно отсутствия жёсткой
  привязки к фиксированному набору территорий) — нарисованный кастомный
  полигон уже работает на любых координатах через мок, но стоит
  прогнать сценарий целиком (выбор далёкого от демо-регионов места) перед
  сдачей и убедиться, что ничего не ломается визуально/логически.

## Известные несоответствия / доработки

- **Демо-сценарий не соответствует реальным данным.** Моковые регионы
  (Меконг, Парадайз/Калифорния, Рондония) — международные кейсы
  засухи/пожара/вырубки. Реальный `../data/train_dataset.csv` — это степная
  зона юга России (озимая пшеница, зерновые, подсолнечник, пастбища), без
  географических координат вообще. Когда появятся реальные координаты
  полигонов (см. открытый вопрос в `backend.md`, п.0) — перегенерировать
  моковые полигоны/сценарии под реальную культуру и регион, либо просто
  переключиться на `HttpVegetationDataService`.
- **Подключение к реальному бэкенду.** Сейчас `../frontend/lib/main.dart` выбирает мок
  по умолчанию; когда бэкенд поднимется — включить
  `--dart-define=API_BASE_URL=...` (или `/api`, если через Caddy —
  см. `../infra/README.md`) и просто проверить, что модели
  (`NdviPolygon`/`NdviPoint`/`Anomaly`) парсят реальные ответы без правок.
- **`POST /polygons/custom`** — во фронте уже вызывается при рисовании
  полигона; на бэкенде такого эндпоинта пока нет (см. `backend.md`).
  Без него режим «нарисовать свой полигон» работает только на моках.
- Крупных пробелов в самом UI (экраны/навигация/адаптив под мобилку и веб)
  на момент записи не видно — стоит перепроверить после того, как
  появятся реальные данные и реальный сценарий выбора территории.
